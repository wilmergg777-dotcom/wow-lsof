 ASTROIO — CÓMO ACTUALIZAR LA APK EN TU SERVIDOR
════════════════════════════════════════════════════════════════

La app comprueba SIEMPRE, al abrirse, este archivo:

    https://astroio.duckdns.org/apk/version.json

Si el "versionCode" de ese archivo es MAYOR que el de la APK
instalada, la app descarga e instala la nueva versión sola y no
deja entrar al juego hasta que termine la actualización.

────────────────────────────────────────────────────────────────
 PASOS PARA PUBLICAR UNA NUEVA VERSIÓN
────────────────────────────────────────────────────────────────

1) Sube la versión de la app:
   - Edita apk/android/app/build.gradle → versionCode (+1) y
     versionName (ej. "1.0.1").
   - Haz push a la rama Xnovaaaa.
   - GitHub Actions compila y te da DOS archivos: AstroIO.apk y
     version.json (en "Artifacts" del workflow, o en el Release
     "apk-vX" del repositorio).

2) Entra por FTP (o al panel de tu servidor) y crea la carpeta:

       /var/www/.../apk/

3) Sube AstroIO.apk a esa carpeta.

4) Abre el version.json que generó el workflow (ya trae el SHA256
   correcto) y súbelo también a esa carpeta. Debe quedar así:

   {
     "versionCode": 3,
     "versionName": "2.4.1",
     "url": "https://astroio.duckdns.org/apk/AstroIO.apk",
     "sha256": "<el sha256 que genera el workflow>"
   }

   IMPORTANTE: el "versionCode" del JSON debe ser IGUAL al que
   pusiste en build.gradle. El "url" ya apunta a tu servidor.

5) Comprueba en el navegador:
       https://astroio.duckdns.org/apk/version.json
   Debe mostrar el JSON. Si te da 404, revisa la ruta/carpeta.

6) Listo. Los jugadores con la app antigua, al abrirla, se
   actualizarán solos y después entrarán al juego.

────────────────────────────────────────────────────────────────
 LAUNCHERS DE PC (Windows + Linux) — misma mecánica
────────────────────────────────────────────────────────────────

Los launchers de PC también se auto-actualizan leyendo ESTE MISMO
archivo version.json. El bloque "launcher" del JSON indica:

   - launcher.versionCode : versión actual del launcher
   - launcher.windows     : url + sha256 del .exe de Windows
   - launcher.linux       : url + sha256 del binario de Linux

PUBLICAR UNA VERSIÓN NUEVA DEL LAUNCHER (sin tocar la APK):

1) Edita launcher/main.go → launcherVersionCode (+1).
2) Ejecuta  bash launcher/build.sh  (o deja que el workflow de
   GitHub Actions lo compile: compila APK + launchers juntos).
3) Crea en el servidor la carpeta   /launcher/   (raíz del dominio)
   y sube ahí los 2 archivos:
       AstroIO-Launcher-windows.exe
       AstroIO-Launcher-linux
4) Actualiza el bloque "launcher" del version.json con las urls y
   los sha256 nuevos y súbelo a /apk/ como siempre.
5) Comprueba en el navegador:
       https://astroio.duckdns.org/launcher/AstroIO-Launcher-linux
   Debe descargar el archivo (si da 404, revisa la carpeta).

Cuando un jugador abre el launcher, este compara el versionCode
del bloque "launcher" con el suyo: si el del servidor es mayor,
se descarga el nuevo, verifica su SHA-256, se reemplaza a sí mismo
y abre el juego con la versión nueva. La APK, el launcher de
Windows y el de Linux se actualizan del mismo tirón al cambiar la
versión, porque todos leen el mismo version.json.

────────────────────────────────────────────────────────────────
 NOTAS
────────────────────────────────────────────────────────────────
- Si el archivo version.json NO existe todavía, la app entra al
  juego directamente (útil la primera vez, antes de subir nada).
- Si el jugador no tiene Internet, la app muestra un aviso
  genérico ("Sin conexión...") SIN mostrar el dominio del
  servidor.
- El SHA256 evita que se instale un paquete corrupto o
  modificado durante la descarga.
- La APK no puede abrirse si está firmada con otro certificado
  (protección contra APK Editor) ni si detecta una app de
  edición de APK instalada.
